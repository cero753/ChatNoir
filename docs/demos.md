# Run the demonstrations

All examples use synthetic local data. Python 3.10+ and Git are enough; no model, server, account or network access is needed.

```sh
python3 scripts/demo.py
```

[Full recorded stdout](demo-output.txt) comes from an actual run of that command. A short excerpt appears in the README. Exact temporary Git IDs can differ across runs because commits include timestamps.

## 1. SQL injection → verified parameter binding

`examples/sql-injection/vulnerable/app.py` inserts an owner value directly into SQL. The baseline produces a CN004 candidate at the query-construction line. It does not establish public application reachability.

```sh
python3 chatnoir.py scan examples/sql-injection/vulnerable
python3 examples/sql-injection/reproduce.py
python3 chatnoir.py scan examples/sql-injection/fixed
```

The reproducer calls the original functions with a crafted owner value against an in-memory SQLite database. It observes two records from the vulnerable function and zero from the parameter-bound function; a legitimate Alice query returns one record in both. This demonstrates the SQL boundary failure and the local fix. Authentication, routing, deployment and other database engines are outside this fixture.

[Baseline candidate report](../examples/reports/sql-baseline.json) · [SARIF export](../examples/reports/sql-baseline.sarif.json) · [Runtime-backed review](../examples/reports/sql-reviewed.md)

The reviewed report is a human-authored interpretation of inspected source and the actual reproducer. It is not generated by the baseline scanner, and it claims only the demonstrated fixture behavior.

## 2. A dangerous-looking call that is not an injection flaw

```sh
python3 chatnoir.py scan examples/false-positive
```

The helper flags `eval`, but source inspection shows a constant expression and no caller-controlled input. The review dismisses the proposed injection with that counterevidence. This example makes the candidate/confirmed distinction visible; it does not establish general false-positive accuracy.

## 3. Know exactly which patch you reviewed

The demo constructs two local fixture commits and binds them to an exact diff digest. To inspect your own committed comparison:

```sh
python3 chatnoir.py diff /path/to/your-app --base main --head HEAD
```

The output includes full commit IDs, patch SHA-256 and changed paths. Deleted paths remain in the inventory. It is evidence identity, not a security or merge verdict. Ask your agent to use the patch-review workflow to inspect behavior and affected callers.

## Try the skill with your agent

Install ChatNoir, then ask:

```text
Use ChatNoir to review examples/sql-injection/vulnerable.
Keep it read-only. Validate against the synthetic reproducer if appropriate,
and distinguish the demonstrated function-level failure from unknown app exposure.
```

Expected behavior: a source-backed explanation of the SQL injection, an explicit validation method, a legitimate control, and a narrow remedy. The exact wording depends on the model. The published local runtime demo does not imply that every supported host's model session has been tested.
